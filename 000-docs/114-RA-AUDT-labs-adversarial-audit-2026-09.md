**Why this exists.** Two conferences are on the calendar (SF Tech Week, Oct 5–11; AI Engineer Code Summit, Nov
10–12, speaker applications close Oct 11). Every talk or format we could propose leans on one claim: _Labs
evaluates real artifacts and publishes evidence a stranger can verify without trusting us._ This audit tried to
make that claim lie before an audience does.

**Verdict, up front.** The chain is real: a nightly GitHub Actions run evaluates 14 pinned marketplace skills with
a paid judge, wraps each result in a kernel-valid `gate-result/v1` row, signs it keyless with cosign, and the
Rekor entry, the certificate identity, and the workflow ref all check out with tools we did not write. The
dashboard refuses to render what it cannot verify. Two P1 defects were found and fixed in the process; neither
was in the signing or verification path, both were in _what gets signed_ (a dead judge was signed as
`advisory`) and _what the ingest was told to trust_ (a stale repo name after a rename). Open items are P2/P3.

---

## 1. Method

- **Trace first, then attack.** The path was read end-to-end from code, not from READMEs, then exercised on a
  scratch copy: never against the production ingest snapshot, never with a production signing identity.
- **Independent verification.** Signatures and transparency-log entries were checked with `cosign verify-blob`
  (`--new-bundle-format`, `--certificate-identity`, `--certificate-oidc-issuer`), sigstore-python
  (`uvx --from sigstore sigstore verify identity`), and the public Rekor API by log index. The estate's own
  verifier (`src/ingest/verifier-sigstore.ts`) was treated as the thing under test, not as an oracle.
- **Evidence discipline.** Every row below cites a path, a command, a CI run, or a Rekor index. Anything not
  exercised says so.
- **No secrets.** Attack runs that needed a bad credential used a garbage value; no key values, tokens, or
  decrypted env content appear in this record or in the scratch artifacts.

## 5. What the earlier pass got wrong

The first write-up of this audit said "the nightly roster never passes `--run-self-test`". That was false:
`eval-roster/run-roster.mjs` has passed it since the roster was created. The real gap is narrower (F5). It is
recorded here because a conference audience will ask exactly this kind of question, and the answer has to be
the one the code gives.

## 6. Is Labs real

Yes, with two qualifications an honest talk must state:

1. **The judge is a paid LLM and it flaps.** The platform discloses this (`flap-report.json`, `agreement` per
   criterion) rather than hiding it. That disclosure is the differentiator, not the accuracy.
2. **The evidence is about a July snapshot of the skills.** Until the pin refresh (F4) is routine, "verified"
   means "verified for the commit named in the row", which the page should say in words.

Everything a skeptic can check without us — signature, identity, Rekor inclusion, schema validity,
tamper-evidence — checks. The two things a skeptic could not have seen (a dead judge dressed as uncertainty,
a stale pin after a rename) are fixed with tests that fail on the mutant.
